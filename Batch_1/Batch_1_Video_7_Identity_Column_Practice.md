
# Batch 1 – Video 7: Identity Column in SQL Server

## 2. What Is an IDENTITY Column?

An IDENTITY column is a column whose values are automatically generated by SQL Server when a new record is inserted.

It is commonly used for generating unique numeric identifiers.

Example:

```sql
CREATE TABLE tblPerson
(
    PersonId INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(20)
);
```

### Understanding IDENTITY(1,1)

The syntax is:

```sql
IDENTITY(seed, increment)
```

| Property | Meaning |
|---|---|
| Seed | Starting value |
| Increment | Value added for each new record |

For `IDENTITY(1,1)`:

- First record receives 1.
- Second record receives 2.
- Third record receives 3.

Both seed and increment are optional. If omitted, SQL Server defaults to 1 for each.

## 3. Insert Records Without Specifying the Identity Column

Since SQL Server automatically generates PersonId, we only need to provide the Name.

```sql
INSERT INTO tblPerson
VALUES ('Sam');

INSERT INTO tblPerson
VALUES ('Sara');
```

Check the records:

```sql
SELECT * FROM tblPerson;
```

Expected output:

| PersonId | Name |
|---:|---|
| 1 | Sam |
| 2 | Sara |

**Important:** SQL Server automatically generated PersonId values.

Recommended practice is to specify the column list:

```sql
INSERT INTO tblPerson (Name)
VALUES ('John');
```

---

## 4. What Happens If We Explicitly Insert an Identity Value?

Try executing:

```sql
INSERT INTO tblPerson
VALUES (1, 'Todd');
```

You will receive an error because SQL Server does not allow explicit identity values by default.

To insert an explicit identity value, we need to enable IDENTITY_INSERT.

---

## 5. Understand Why Deleted Identity Values Are Not Reused

Let's insert another record:

```sql
INSERT INTO tblPerson (Name)
VALUES ('Todd');
```

Check the table:

```sql
SELECT * FROM tblPerson;
```

Now delete Todd:

```sql
DELETE FROM tblPerson
WHERE Name = 'Todd';
```

Insert another record:

```sql
INSERT INTO tblPerson (Name)
VALUES ('Alex');
```

Check the records:

```sql
SELECT * FROM tblPerson;
```

Expected output:

| PersonId | Name |
|---:|---|
| 1 | Sam |
| 2 | Sara |
| 4 | Alex |

**Observation:**

PersonId 3 is missing.

SQL Server does not automatically reuse an identity value simply because its corresponding record was deleted.

Identity values are not guaranteed to be gap-free.

---

## 6. How to Insert an Explicit Identity Value

Suppose PersonId 3 is missing and we want to insert a record using that value.

### Step 1: Enable IDENTITY_INSERT

```sql
SET IDENTITY_INSERT tblPerson ON;
```

### Step 2: Specify the column list

```sql
INSERT INTO tblPerson (PersonId, Name)
VALUES (3, 'John');
```

### Step 3: Verify the records

```sql
SELECT * FROM tblPerson;
```

Expected output:

| PersonId | Name |
|---:|---|
| 1 | Sam |
| 2 | Sara |
| 3 | John |
| 4 | Alex |

### Step 4: Turn IDENTITY_INSERT OFF

```sql
SET IDENTITY_INSERT tblPerson OFF;
```

**Important rules:**

- When IDENTITY_INSERT is ON, you must explicitly provide a value for the identity column.
- You must specify the column list in the INSERT statement.
- Only one table per session can have IDENTITY_INSERT set to ON at a time.
- Turn it OFF after completing the explicit insert.

---

## 7. What Happens If We Forget to Turn IDENTITY_INSERT OFF?

Try the following:

```sql
SET IDENTITY_INSERT tblPerson ON;

INSERT INTO tblPerson (Name)
VALUES ('David');
```

SQL Server returns an error because the identity value must be explicitly supplied while IDENTITY_INSERT is ON.

Turn it OFF:

```sql
SET IDENTITY_INSERT tblPerson OFF;
```

Now try again:

```sql
INSERT INTO tblPerson (Name)
VALUES ('David');
```

This insert should work normally.

## 8. Understanding Seed and Increment with Another Example

Create a table with a different seed and increment:

```sql
CREATE TABLE tblEmployee
(
    EmployeeId INT IDENTITY(100,5) PRIMARY KEY,
    EmployeeName NVARCHAR(50)
);
```

Insert records:

```sql
INSERT INTO tblEmployee (EmployeeName)
VALUES ('Ravi');

INSERT INTO tblEmployee (EmployeeName)
VALUES ('Kiran');

INSERT INTO tblEmployee (EmployeeName)
VALUES ('Priya');

SELECT * FROM tblEmployee;
```

Expected output:

| EmployeeId | EmployeeName |
|---:|---|
| 100 | Ravi |
| 105 | Kiran |
| 110 | Priya |

**Observation:**

The first identity value is 100, and every subsequent value increases by 5.

## 9. Reset Identity Using DBCC CHECKIDENT

Suppose we delete all records from tblPerson and want to restart the identity values.

### Step 1: Delete all records

```sql
DELETE FROM tblPerson;
```

### Step 2: Reseed the identity column

```sql
DBCC CHECKIDENT ('dbo.tblPerson', RESEED, 0);
```

### Step 3: Insert a new record

```sql
INSERT INTO tblPerson (Name)
VALUES ('New Person');
```

### Step 4: Verify

```sql
SELECT * FROM tblPerson;
```

Expected output:

| PersonId | Name |
|---:|---|
| 1 | New Person |

**Why did PersonId restart at 1?**

We reseeded the identity value to 0. With an increment of 1, the next generated value is 1.

Note: This example assumes the table previously contained records and was emptied using DELETE.

## 14. Important Learning Note

An IDENTITY column automatically generates numeric values, but it does not guarantee gap-free numbering.

In real-world applications, identity columns are commonly used to generate surrogate keys and record identifiers.

Do not depend on identity values to represent business sequence numbers such as invoice numbers unless the application has a separate numbering strategy.
