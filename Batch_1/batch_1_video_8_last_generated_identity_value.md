
# Batch 1 – Video 8: How to Get the Last Generated Identity Value in SQL Server

## 2. Introduction

In the previous lesson, we learned that SQL Server automatically generates values for IDENTITY columns.

But suppose you insert a new employee into a table and want to know the EmployeeId generated by SQL Server.

How can you retrieve that value?

SQL Server provides three commonly used methods:

```sql
SELECT SCOPE_IDENTITY();

SELECT @@IDENTITY;

SELECT IDENT_CURRENT('tblPerson');
```

Let's understand each method with practical examples.

---

## 3. Prepare the Practice Table

Create a table with an IDENTITY column.

```sql
CREATE TABLE tblPerson
(
    PersonId INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(50)
);
```

Insert two records:

```sql
INSERT INTO tblPerson (Name)
VALUES ('Sam');

INSERT INTO tblPerson (Name)
VALUES ('Sara');
```

Verify the records:

```sql
SELECT * FROM tblPerson;
```

Expected output:

| PersonId | Name |
|---:|---|
| 1 | Sam |
| 2 | Sara |

Now let's retrieve the last generated identity value.

---

## 4. Method 1: SCOPE_IDENTITY()

`SCOPE_IDENTITY()` returns the last identity value generated in the same session and the same scope.

Execute:

```sql
INSERT INTO tblPerson (Name)
VALUES ('John');

SELECT SCOPE_IDENTITY() AS LastGeneratedIdentity;
```

Expected output:

| LastGeneratedIdentity |
|---:|
| 3 |

### Understanding Scope

A scope is the execution context in which SQL statements run.

Examples include:

- A stored procedure.
- A function.
- A trigger.
- A batch of SQL statements.

`SCOPE_IDENTITY()` returns the last identity value generated in the current scope.

**Important:** If no identity value has been generated in the current scope, `SCOPE_IDENTITY()` returns NULL.

---

## 5. Method 2: @@IDENTITY

`@@IDENTITY` returns the last identity value generated in the current session, regardless of scope.

Execute:

```sql
INSERT INTO tblPerson (Name)
VALUES ('David');

SELECT @@IDENTITY AS LastGeneratedIdentity;
```

Expected output:

| LastGeneratedIdentity |
|---:|
| 4 |

### Understanding the Difference

The important difference is that `@@IDENTITY` considers identity values generated in other scopes within the same session.

For example, if a trigger inserts a record into another table, `@@IDENTITY` may return the identity generated by that trigger.

We will demonstrate this in Section 7.

---

## 6. Method 3: IDENT_CURRENT()

`IDENT_CURRENT()` returns the last identity value generated for a specific table, regardless of session or scope.

Syntax:

```sql
SELECT IDENT_CURRENT('table_name');
```

Example:

```sql
SELECT IDENT_CURRENT('dbo.tblPerson') AS LastGeneratedIdentity;
```

Expected output:

| LastGeneratedIdentity |
|---:|
| 4 |

### Understanding IDENT_CURRENT()

Unlike the previous two methods, `IDENT_CURRENT()` is associated with a specific table.

It does not depend on the current session or scope.

For example:

- Session 1 inserts a record into tblPerson.
- Session 2 can retrieve that table's latest identity value using IDENT_CURRENT().

**Important:** Because another session may insert a record at any time, IDENT_CURRENT() is not a safe way to retrieve the identity value generated by your own INSERT statement.

---

## 7. Practical Example: Understanding the Difference Using Triggers

This is the most important practical exercise in this lesson.

Suppose we have two tables:

- tblPerson1
- tblPerson2

Whenever a record is inserted into tblPerson1, a trigger automatically inserts another record into tblPerson2.

### Step 1: Create the First Table

```sql
CREATE TABLE tblPerson1
(
    PersonId INT IDENTITY(1,1) PRIMARY KEY,
    Name NVARCHAR(50)
);
```

### Step 2: Create the Second Table

Notice that this table starts its identity values at 100.

```sql
CREATE TABLE tblPerson2
(
    PersonId INT IDENTITY(100,1) PRIMARY KEY,
    Name NVARCHAR(50)
);
```

### Step 3: Create a Trigger

```sql
CREATE TRIGGER trg_InsertIntoPerson2
ON tblPerson1
AFTER INSERT
AS
BEGIN
    INSERT INTO tblPerson2 (Name)
    SELECT Name
    FROM inserted;
END;
```

**What does this trigger do?**

Whenever a record is inserted into tblPerson1, SQL Server automatically inserts the same Name into tblPerson2.

### Step 4: Insert a Record into tblPerson1

```sql
INSERT INTO tblPerson1 (Name)
VALUES ('Sam');

SELECT * FROM tblPerson1;

SELECT * FROM tblPerson2;
```

Expected output:

**tblPerson1**

| PersonId | Name |
|---:|---|
| 1 | Sam |

**tblPerson2**

| PersonId | Name |
|---:|---|
| 100 | Sam |

Two identity values were generated:

- PersonId 1 in tblPerson1.
- PersonId 100 in tblPerson2.

### Step 5: Compare All Three Methods

Execute:

```sql
SELECT
    SCOPE_IDENTITY() AS ScopeIdentity,
    @@IDENTITY AS AtAtIdentity,
    IDENT_CURRENT('dbo.tblPerson1') AS IdentCurrentPerson1,
    IDENT_CURRENT('dbo.tblPerson2') AS IdentCurrentPerson2;
```

Expected output:

| ScopeIdentity | AtAtIdentity | IdentCurrentPerson1 | IdentCurrentPerson2 |
|---:|---:|---:|---:|
| 1 | 100 | 1 | 100 |

### Why Are the Results Different?

**SCOPE_IDENTITY() = 1**

The identity value generated in the current scope was 1, from tblPerson1.

The trigger executes in a different scope, so its identity value is not returned by SCOPE_IDENTITY() in the outer INSERT scope.

**@@IDENTITY = 100**

It returns the last identity value generated in the current session, including identity values generated inside triggers.

Therefore, it returns 100 from tblPerson2.

**IDENT_CURRENT('dbo.tblPerson1') = 1**

It returns the latest identity value generated for tblPerson1.

**IDENT_CURRENT('dbo.tblPerson2') = 100**

It returns the latest identity value generated for tblPerson2.

---

## 8. Comparison of All Three Methods

| Feature | SCOPE_IDENTITY() | @@IDENTITY | IDENT_CURRENT() |
|---|---|---|---|
| Same session | Yes | Yes | No requirement |
| Same scope | Yes | No | No requirement |
| Specific table | No | No | Yes |
| Affected by trigger identity | No, if trigger is in another scope | Yes | Depends on specified table |
| Affected by other sessions | No | No | Yes |

### Quick Revision

- `SCOPE_IDENTITY()` – Same session and same scope.
- `@@IDENTITY` – Same session, across scopes.
- `IDENT_CURRENT()` – Specific table, across sessions and scopes.

**Recommended approach:** Use `SCOPE_IDENTITY()` when you need to retrieve the identity value generated by your own INSERT statement.

## 13. Important Learning Note

In real-world SQL Server development, identity values are often required immediately after inserting a record.

For retrieving the identity generated by your own INSERT statement, SCOPE_IDENTITY() is generally the preferred method over @@IDENTITY and IDENT_CURRENT().

Remember:

- SCOPE_IDENTITY() protects against identity values generated in a different scope, such as a trigger.
- @@IDENTITY can return an identity generated by a trigger.
- IDENT_CURRENT() is table-specific but can be affected by inserts from other sessions.

Understanding these differences is important when building reliable database applications.
